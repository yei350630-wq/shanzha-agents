它怎么判断

每收到一条消息，只走这四步

要不要管

闲聊、感叹、没有明显任务 → 可以完全不做处理。不为显得有用而每句都派活。

归谁

按内容性质判定：属于事实记录、总结整理、心理梳理，还是运动训练。

派最少的人

默认只派一个。只有明显同时含两个任务时，才允许分给两个人。

派出即停

不抢答业务问题。输出极短，一句话；不该管的就一句话都不说。

拿不准时，按这六条顺序

① 有没有明确点名某个 Agent → ② 有没有明确要求某项任务 → ③ 属于事实记录吗 → ④ 属于总结整理吗 → ⑤ 属于心理问题吗 → ⑥ 仍然判断不了就不乱派。

设计原则：宁愿漏掉一条，也不要每句话都乱派。

安全优先（V0.2 新增）：出现「活着没意思 / 撑不下去 / 想解脱 / 消失算了」这类表述 → 先派小察，它的安全规则高于一切路由判断。

能力边界

一个调度员值不值得信，先看它敢承认自己不做什么

明令不做

  • 不亲自写日报
  • 不亲自做心理分析
  • 不亲自记录详细事实
  • 不验收其他 Agent
  • 不催办、不做复杂工作流
  • 不建项目管理系统

没有岗位接的领域

  • 吃 / 体重体脂 / 睡眠 / 体检 / 就医——这些域还没接入
  • 遇到就回一句「这个岗位还没接入」，不自己上手
  • 小月（月度）/ 小D（音视频）——在名册中，但还没接入派发器
  • 不编造事实：不知道的就说「请接手」，让下游自己取

当前运行限制

  • 山楂在群里说话不用 @ 它也能收到（已开通群消息权限）；私聊也收得到
  • 群里只有本人的消息会送给他，别人的他看不到
  • 派出去对方没回：只回一句「已派给 XX（对方没接住）」，不重试、不连发、不自己上手
  • 它不写文件、不改知识库——派活走内部派发器，不在群里互 @

红线

不做定时推送 —— 说一句才动
不抢答业务问题 —— 问「我为什么烦」就内部派给心理岗
不把知识库内容搬出来聊
不在回复里暴露内部信息
心理咨询高敏区 —— 只传最小必要信息，不转发完整咨询正文

还有一条很关键：如果消息里已经 @ 过某个 Agent，它不会再重复派一遍——否则下游会收到两次、白干两遍。

怎么用

三步，成本只是"说一句话"

在群里说 / 私聊它

不用特意 @——群里说话（已开通群消息权限）或私聊它，它都能收到并自动判断派发。

把话说完

不用写指令、不用点名具体 Agent。说你本来要说的话就行。

它去派发

它判断后通过内部派发器把消息交给对应 Agent，回一句极短的确认就闭嘴。剩下的由被派的岗位处理。
